# Human-shaped software: the vision

*Ben Wilkoff, October 1, 2026. Written by Ben; dictation slips fixed,
nothing else changed. This is the reference for every decision about
humanshaped.org and how it relates to the Universal App Template.*

Human-shaped software, or human-shaped apps, are all about solving for
human-shaped problems and making sure that whatever we build, it's not
trying to force humans into computer-based solutions.

The courses available at humanshaped.org are highly engaging and
interactive, and take you from an idea you have for solving a
human-shaped problem to the point of shipping an app on one or more
platforms that solve that problem.

You should be able to sign up for a cohort that will last approximately
five weeks, with a synchronous video event each week. You should be able
to engage in challenge-based, practical activities that help you along
the process of building human-shaped software. The activities will make
use of a GitHub repository and all of the features found within it, a
Claude or Gemini that allows for coding work to be done in that GitHub
repository, and a desktop computer based setup that will allow for both
local and cloud-based iteration and testing.

Throughout the course you should be able to submit your current
iteration or ideas for the app to the teacher for feedback, and you
should also be able to submit it to an AI-based feedback system that is
based upon our approach to software development.

You should also be able to interact with the other people in the cohort
and be able to see their works in progress as they are building.
Ideally we would make use of the conversation features built directly
into GitHub, but they would also be integrated into the website, so
that the website forms a centralized hub of information about every app
that's being built with the human-shaped software methodology.

The synchronous sessions being conducted on Google Meet should have
features dedicated to both the student and the teacher that provide more
functionality than a regular Google Meet experience provides. You should
be able to bring in things from GitHub or from the hub website easily,
and it should somehow integrate with whatever AI chatbot you are
currently using to help you in that regard.

Ideally, the humanshaped.org website is a place that functions as the
hub for everything to do with human-shaped software being built around
the world. It may start off as a hub for these courses, but ideally it
should become a digital hub for anyone building software for people
instead of profit.

You should be able to log in with your GitHub credentials, see your
cohort information and any of the apps that have been built or are in
progress within your cohort, submit something to your teacher for
feedback, connect your AI agent to have a conversation and get feedback
using our system and tools, and have conversations with your other
cohort members.

The website itself should not have the same design as any of the
existing human-shaped software that has been built, so we may need to
create our own design language that functions as part learning
management system, part social networking hub, and part movement
catalyst.

The way that the website should interact with the GitHub template
should be almost entirely seamless. The only reason why there is any
separation is that I don't want people to have to get the pages from
humanshaped.org as a part of their template when they are building
human-shaped software on their own. So any change that we make to the
website or to the template itself should be represented and designed
for the right audience. The audience for the template is anybody who
wants to go it alone with human-shaped software. The audience for the
website is anyone who wants to be a part of the community, or wants to
be involved in a cohort, or wants to start a human-shaped software event
or idea for themselves.

On the website, there should be a toolkit of sorts for sharing the ideas
about human-shaped software, proclaiming that your software is
human-shaped, or that would allow you to start an event or conversation
or community of your own around your own human-shaped software
processes.

The goal is for these ideas to be free, the methodology to be free, and
the tools to be free. There may come a time where I end up charging to
be a part of a human-shaped software cohort, but that is not the primary
focus, and we would only bring up that possibility if my time to run the
cohort became an issue.

That means that, theoretically, other people should be able to become
teachers within the website and lead their own cohort of human-shaped
software.

That means also that we need to look at other ways of lowering the
barrier to entry, and we should research how to publish other people's
apps under a single developer account for Google Play or Apple's App
Store.

We should also figure out ways to ensure that all human-shaped software
doesn't look the same because it started from the same template. We
need to figure out ways to allow users or students to differentiate the
design of their app from the other folks within a cohort.

In a way, what we are building is a human-shaped learning environment.
It is learner focused, and should allow for many different entry points
that people can hold onto, understand, and run with.
